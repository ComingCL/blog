## 修改内容摘要

生产 Docker 构建改用 Go `1.26` 和 Node `22-slim`，默认从 DaoCloud Docker 官方镜像代理拉取 PostgreSQL、Caddy、Go、Node 镜像；Go 构建阶段设置模块代理和本地工具链模式。部署脚本在 Docker CLI 缺失时给出明确提示，并允许已有生产目录安全切换镜像源而不轮换凭据或数据。

本次使用独立临时 Compose 项目完成了应用镜像构建、PostgreSQL 初始化、迁移、管理员初始化、应用与 Caddy 健康检查及 `/v1/readyz` HTTP 验证，验证后已清理隔离容器、卷、网络和临时凭据目录。

## 修改内容详情

### 1. 生产镜像和构建源

- `deploy/Dockerfile`：默认 Go 基础镜像改为 `m.daocloud.io/docker.io/library/golang:1.26`，Node 改为 `m.daocloud.io/docker.io/library/node:22-slim`；Go 构建阶段接受 `GOPROXY`，并设置 `GOTOOLCHAIN=local`。
- `scripts/deploy.py`：生产 Compose 默认镜像源改为 `m.daocloud.io/docker.io/library`，构建参数传入 Go `1.26`、Node `22-slim` 和 `https://goproxy.cn,direct`。
- `scripts/deploy.py`：域名、项目名和网段仍是部署身份；已有目录传入新的 `--registry` 时只更新镜像引用和状态文件，不重新生成密码或卷。
- `README.md`、`docs/deployment.md`、`harness/system-design.md`：同步镜像标签、默认源和构建行为说明。

### 2. Docker 缺失提示

- `scripts/deploy.py`：捕获 Docker CLI 缺失，输出安装 Docker Engine 和 Compose v2 的可执行提示，不再只显示 `FileNotFoundError`。
- `scripts/test_deploy.py`：增加 Docker CLI 缺失行为测试以及生产构建参数测试。

## 验证结果

### 反事实与 Red → Green

- 反事实场景：旧实现仍使用 `golang:1.26.10-bookworm`、`node:22-bookworm-slim`，Docker 缺失时只输出 `FileNotFoundError`，已有生产目录也无法安全切换镜像源。
