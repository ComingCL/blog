## 修改内容摘要

生产镜像从 `node:22-slim` 升级到当前生产适用的 Node 26 完整镜像，避免 slim 镜像缺少系统证书和工具导致 APT 引导失败。Docker 官方镜像、APT、npm、Go 模块下载源均由部署参数控制，默认使用 DaoCloud、阿里云、npmmirror 与 goproxy.cn。

## 修改内容详情

### 1. 构建镜像和下载源

- 原因与行为：截图中的 `apt-get` 默认访问 Debian 官方源，`npm ci` 默认使用 npm 官方源；完整镜像不再使用 slim 变体。运行时会在安装系统包前替换 Debian 与 Debian Security 源，默认使用阿里云 HTTPS 镜像；Node 26 完整镜像已验证可以直接完成 HTTPS APT 引导，npm 与 Go 源同样使用 HTTPS。
- 关联文件：`deploy/Dockerfile`、`scripts/deploy.py`。
- 核心设计影响：新增 `--apt-mirror`、`--npm-registry`、`--goproxy` 参数；所选构建源写入忽略的 `deploy/runtime/production/state.json`，后续重复部署沿用或显式切换，不轮换凭据、不清空数据。

### 2. 文档与回归测试

- 原因与行为：让服务器部署时明确知道四类源的默认值、覆盖方式和完整 Node 镜像支持 HTTPS APT 的验证结果。
- 关联文件：`docs/deployment.md`、`README.md`、`harness/system-design.md`、`scripts/test_deploy.py`。
- 核心设计影响：保持生产凭据、数据卷、origin 和项目身份不变；只刷新构建参数。
