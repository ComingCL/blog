修复已发布文章含 Markdown 链接时，API 返回完整正文但 Next.js 服务端渲染失败的问题。应用错误日志直接写入部署目录下的宿主机文件，增加可关联的 request ID、渲染 digest 和安全错误分类。

## 修改内容详情

### 1. 文章正文服务端渲染

- 原因：`Content.tsx` 在服务端渲染每个 Markdown 链接时，调用了 `"use client"` 模块 `MediaPreview.tsx` 导出的 `isVideoURL()`。普通链接也触发 React 服务端／客户端边界错误；编辑器在客户端运行，因此预览正常不代表发布页正常。
- 将媒体 URL 识别移入纯函数模块，客户端弹框仍通过 JSX 渲染，保留图片和视频预览行为。
- 关联文件：`web/src/components/media.ts`、`web/src/components/Content.tsx`、`web/src/components/MediaPreview.tsx`、`web/src/components/MarkdownImage.tsx`。
- 新增 `scripts/smoke_deployment.py`：仅允许回环高位 HTTP 端口且项目名以 `-smoke` 结尾的隔离部署；通过真实 Cookie／CSRF 完成创建、保存、发布，再验证匿名 API 正文和生产 SSR 页面。

### 2. 前后端错误定位

- HTTP 入口生成 request ID，传入 SSR／Go 并回传浏览器；拒绝直接信任外部传入的 ID。
- `serverApi` 对网络、超时、HTTP 和异常响应分别记录安全诊断，正常成功和预期 404 不新增错误日志。
- Next.js `onRequestError` 记录路由模板、request ID、digest 和错误分类；错误页显示编号并使用安装版本要求的 `retry()`，不再误判一定是后端不可用。
- Go 内部错误／数据库日志保留路由、IP、已认证用户身份、错误类型、根因类型和合法 SQLSTATE；不输出原始错误正文、数据库 Detail/Hint、SQL 或私有配置。
- 关联文件：`web/request-id.mjs`、`web/server.mjs`、`web/src/api/server.ts`、`web/src/instrumentation.ts`、`web/src/telemetry/server-diagnostics.ts`、`web/src/models/enums.ts`、`web/src/app/error.tsx`、`server/src/response/response.go`、`server/src/infrastructure/db/connection.go`、`server/src/logger/failure.go`、`server/src/cmd/api/main.go`。

### 3. 宿主机日志文件

- Compose 将 `<部署目录>/logs/app` 挂载到 `/app/data/logs`，部署脚本打印实际绝对路径。默认是 `<项目绝对路径>/deploy/runtime/production/logs/app`。
- `application.jsonl` 保留 Go 应用日志；`error.jsonl` 仅 ERROR 及以上，两者包含代码位置并同步到 Docker 输出。
- Supervisor 将脱敏 Web 输出写入 `web.jsonl`／`web-error.jsonl`，进程生命周期写入 `runtime.jsonl`，Go 启动／panic 标准错误写入 `api-stderr.jsonl`。
- 交叉审查补齐 Go 初始化前 `config_load_failed`／`logging unavailable` 的安全事件白名单映射，避免脱敏时把唯一启动原因一并丢弃；任意 `msg` 仍不记录。
- 文件权限 0600、日志目录 0700；每文件 10 MiB，最多 5 份归档；进程退出前冲刷无换行的最后一条输出。日志目录符号链接被拒绝。
- 关联文件：`scripts/deploy.py`、`deploy/Dockerfile`、`deploy/process-logs.mjs`、`deploy/supervisor.mjs`、`server/src/logger/logger.go`。
- 不修改六张表、事务、业务审计、授权或配置凭据。原 `app_data` 卷保留；旧日志留在卷内但被新挂载遮挡，不自动迁移或删除。Caddy／bootstrap 输出继续通过 Docker Compose logs 查看。
- 文档：`docs/deployment.md`、`docs/monitoring.md`、`harness/system-design.md`。
