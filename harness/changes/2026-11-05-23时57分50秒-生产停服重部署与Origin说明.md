## 修改内容摘要

新增 `redeploy` 部署动作，用于在新镜像构建成功后停止当前生产 Compose 项目、保留数据卷并按数据库到应用的顺序重新启动。补充 `origin` 的作用、域名一致性要求和停服期间行为，避免把公网站点域名与 API 或数据库地址混淆。

## 修改内容详情

### 1. 停服重部署

- `scripts/deploy.py`：新增 `redeploy` action。先执行应用镜像构建，成功后执行当前 Compose 项目的 `stop`，再等待 PostgreSQL、运行 bootstrap、启动应用和 Caddy；不调用 `down -v`，不删除卷，不轮换凭据。
- `scripts/test_deploy.py`：验证构建发生在停止前、步骤顺序正确且不存在删除卷的命令。
- `docs/deployment.md`、`harness/system-design.md`：记录命令、短暂中断、失败时旧服务继续运行及数据保留边界。

### 2. Origin 说明

- `docs/deployment.md`、`harness/system-design.md`：说明 `origin` 是协议、域名和可选端口组成的规范公网站点 Origin，用于 HTTPS 校验、共享配置、Caddy 证书入口、公网就绪检查和 Cookie Secure 属性；它必须与 DNS、备案、Caddy 及浏览器实际访问域名一致。

## 未完成项与后续注意

- `redeploy` 会造成短暂停机；若需要零停机发布，需要单独的双实例或反向代理切换设计。
- 执行前建议先运行 `python3 scripts/deploy.py backup`，并确认 `origin` 与用户实际访问的域名完全一致。
