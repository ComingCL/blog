## 修改内容摘要

补充生产部署入口，生成独立强密码和私有 YAML，通过 Docker Compose 编排 Go／Next.js、PostgreSQL 和 Caddy HTTPS，支持重复部署、初始化、状态、日志和手动备份。整理应用日志，减少重复与探针噪声，补充提交后业务日志及配置错误脱敏；调研并记录监控选型。加强 AGENTS 的测试先行要求。

## 修改内容详情

### 1. 生产配置和容器运行

- `scripts/deploy.py`：域名与网段校验、0700／0600 私有文件、独立随机应用／PG 管理／管理员密码与审计密钥、文件型 secrets、生成 Compose／Caddy、文件锁、构建／数据库就绪／迁移初始化／应用就绪／公网检查编排，以及 status／logs／backup。
- 生产数据库和 Go／Web 不直接发布宿主机端口，仅 Caddy 暴露标准 HTTP(S) 端口；应用角色无超级用户、创建数据库或创建角色权限。开发库、端口、配置与数据卷不参与生产初始化。
- 重复执行保留密码、管理员与数据，刷新可生成的 Compose／Caddy。私有文件不完整时拒绝重生成，防止旧数据卷密码错配。备份为手动、同机输出；不宣称已有自动异机备份或自动覆盖恢复。
- `deploy/Dockerfile`、`deploy/build-config.yaml`、`.dockerignore`：Go 与 Next.js 多阶段构建，真实配置不进入上下文／镜像，构建仅使用公开占位值；框架的 NODE_ENV／遥测选项不作为应用配置源。
- `deploy/app-entrypoint.sh`、`deploy/postgres-entrypoint.sh`：处理本机 0600 文件型 secrets 的属主，应用复制私有配置后降权；`deploy/supervisor.mjs` 管理两个进程、转发退出信号，任一子进程异常时停止另一进程以触发容器重启；`deploy/healthcheck.mjs` 检查数据库就绪与 Web 首页。
- `server/src/service/bootstrap.go`、`server/src/cmd/admin/main.go`：`-if-missing` 仅初始化缺失管理员，已有站点所有者与密码保留，不接受不同身份覆盖。
- `server/src/config/{config.go,config_test.go}`、`server/config/config.example.yaml`、`web/{server-config.mjs,server.mjs}`：Web 监听 IP／端口与公开 HTTPS origin 分离。Go API 保持回环监听，Web 信任明确的 Caddy 地址，来源 IP 沿原可信链传递。
- `web/src/app/robots.ts`：动态读取运行时 origin，避免容器构建占位域名成为静态 robots 地址。

### 2. 日志复核

- `server/src/middleware/{middleware.go,middleware_test.go}`：每次常规请求只打印 access_end；正常健康探针、CSRF 令牌获取、静态图片请求静默，失败仍记录。保留来源 IP、已确认用户名／ID、request ID、状态与耗时；按状态区分 INFO／WARN／ERROR，不打印查询串、请求体或 Cookie。
- `server/src/infrastructure/db/{connection.go,logging_test.go}`：快速查无记录／预期重复不再报警，慢查询和真实错误保留，SQL／参数／原始数据库错误不写日志；迁移输出完成或失败事件。
- `server/src/service/{operation_log.go,operation_log_test.go,app.go,auth.go}`：关键发布、撤回、删除、登录、密码或站点配置等成功事件仅在事务返回成功后打印；自动保存等保持持久化审计，不重复打印业务成功行。
- `server/src/cmd/{api,admin}/main.go`、`web/{server.mjs,server-config.mjs,server-config.test.mjs}`：保留启动退出与关键失败事件；YAML／URL 解析错误不回显私有输入。进程管理仅打印服务名、PID、退出码，不打印启动参数中的配置内容。

### 3. 测试、CI 与项目记忆

- `AGENTS.md` 明确“先写并运行行为失败的单元测试，再针对测试实现”，禁止先写完整实现再补测；部署、配置、初始化、日志和故障处理也受此要求约束。
- `scripts/test_deploy.py`、`deploy/supervisor.test.mjs`：新增生成器、幂等、安全边界、衍生产物刷新、执行顺序、失败停止、进程退出与清理测试。
- `server/src/infrastructure/db/integration_test.go`：真实 PG 中验证重复初始化不重置密码、发布审计失败回滚时无成功日志、成功提交后有关键日志。
- `.github/workflows/ci.yml` 使用 setup.py 生成与 CI 数据库匹配的 YAML，替代直接复制占位 DSN；CI 和 `scripts/test.sh` 接入部署测试。
- `README.md`、`docs/deployment.md`、`docs/monitoring.md`、`harness/{README,system-design}.md`：同步部署命令、密码管理、备份与恢复边界、监控选型和日志规则。
- 监控调研依据为 Docker／Caddy／Uptime Kuma／Netdata／Prometheus／Grafana 官方资料，链接见上述文档。建议外部 Uptime Kuma 检查可用性、Netdata 查看资源，按需后续引入 Prometheus／Grafana／Loki；没有自动安装监控或发送通知。

## 验证结果

### 反事实与 Red → Green

- **部署生成器 Red**：`python3 -m unittest discover -s scripts -p test_deploy.py`。可导入的空契约骨架不生成凭据／配置，不拒绝不安全参数，也不返回部署步骤，初始 6 组测试失败；目标文件缺失是产物未生成，非依赖／导入失败。实现后通过；后续架构分离 PG 管理／应用角色时加强独立密码和最小权限断言。
- **私有目录 Red**：旧生成器允许把密码文件放入公开源码目录；先在临时仓库复现，再限制仓库内输出仅位于忽略的 deploy/runtime。
- **幂等计划刷新 Red**：旧实现重复执行保留了过期 Caddy 产物，定向断言失败；改为只原子刷新衍生配置，保留凭据和状态。
- **监听配置 Red**：Go 拒绝合法新增 web_host／web_port 字段，Node 返回的监听属性缺失；实现共享配置后通过。
- **日志 Red**：旧代码一请求两条访问行，成功探针／令牌请求产生噪声，普通 record-not-found 产生数据库告警；测试先失败后通过。
- **配置脱敏 Red**：Node 原始 Invalid URL 错误包含测试私有输入标识；改用不带原始输入的 YAML／URL 错误，追加 YAML 格式错误回归。
- **管理员 Red**：真实 PG 重复 bootstrap 返回 version conflict；实现缺失才创建后通过，原密码仍可登录。
- **提交日志 Red**：单元测试观察不到关键业务成功日志；真实 PG 发布成功后也缺少 post.publish 事件日志。实现后仅提交成功打印；故障注入回滚分支仍不打印成功日志。
- **进程管理 Red**：契约骨架直接返回成功，无法启动／回收子进程，两个测试失败；实现后验证异常退出结束整个组和正常关闭确实回收两个子进程。
- 另补充了执行器失败停止、最终公网检查顺序等回归断言，不把追加的回归检查另行描述为完整 Red 周期。
